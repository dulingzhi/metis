# 界面规格（egui 桌面控制台）

> 相关：[架构](ARCHITECTURE.md) · [功能对齐](PARITY.md) · [开发指南](DEVELOPMENT.md) · [测试](TESTING.md)

> 状态：设计已定，代码未落地（M0）。本文件是 GUI 的**唯一**规格来源；界面上的每条文案、每个开关的存在理由
> 都在这里或 [`HARNESS-MATRIX.md`](HARNESS-MATRIX.md) 里有依据。基线是 agent-purge 的 Web 控制台
> （`http://127.0.0.1:7788`），去掉 Web 特有的东西（端口、浏览器生命周期、同源校验、退出倒计时）。

## 0. 设计原则

1. **控制台不是终端**：只做配置与诊断，不提供会话内交互。
2. **三件事分开显示**：配置已写（磁盘）、历史测试（验证）、当前会话是否生效（宿主自己的事）。
   界面上永远不允许把前两者说成第三者。
3. **不摆点了没反应的开关**：通道不可用时，开关**不显示为可用**，旁边写"为什么不能用"（能力表的 `why`）。
4. **草稿与已保存分开**：表单有未保存修改时显式标记；离开前确认；刷新/重读状态不覆盖草稿。
5. **失败逐项显示**：一次应用里某一家失败，不影响其他家；失败项保留可重试入口。
6. **破坏性操作分级**：`暂停`（保留选择）、`撤销接管`（保留人设）、`删除数据`（**不可逆**）三档在文案和
   配色上必须一眼可分。

## 1. 窗口与整体骨架

```
┌───────────────────────────────────────────────────────────────────────┐
│ 顶栏 TopBottomPanel::top                                            │
│  [● 就绪/应用中…]                    [v0.1.0] [刷新状态] [退出]      │
├────────────┬──────────────────────────────────────────────────────────┤
│ 侧边导航   │ 通知条（可关闭，aria-live 等价：accesskit live region）   │
│ SidePanel  ├──────────────────────────────────────────────────────────┤
│  · 控制台  │                                                          │
│  · 人设库  │            当前屏幕 CentralPanel                          │
│  · 验证诊断│                                                          │
│  · 关于    │                                                          │
│            │                                                          │
│ 底部：本地│                                                          │
│ 配置提示   │                                                          │
└────────────┴──────────────────────────────────────────────────────────┘
```

- 主窗口默认 `1280×860`，最小 `900×620`。窗口几何与面板宽度持久化（eframe persistence）。
- 一次只展开一个执行器详情（避免把 15 家的技术路径铺在首屏）。
- 所有耗时动作都通过 `JobRunner` 在后台跑；界面上表现为"按钮进入忙碌态 + 顶栏状态 + 可取消"。

## 2. 屏幕清单

```rust
pub enum Screen { Console, Library, Diagnostics, About }
```

### 2.1 控制台（Console）—— 等价于基线首页

| 区块 | 内容 | 基线对应 |
|---|---|---|
| 页头 | 标题「控制台」+ 副标题「选好人设，明确范围，再应用。」；右侧 `电源` 按钮 + `撤销全部接管` | `#power`、`#disarm-all` |
| 当前状态条 | 电源徽标（已暂停 / 注入中）、当前人设名、当前模式一句人话、最近一次应用时间（点击跳到诊断页） | `#power-status`、`#current-persona`、`#current-mode`、`#current-sync` |
| 人设与模式面板 | 人设下拉（含描述）+「编辑这份人设」；模式三选一（换身份 / 只留人设 / 追加），每项带一行说明；底部提示「配置写入不代表现有会话已生效。」；`撤销选择`、`应用变更`、`保存并应用` | `#persona-select`、`#edit-current`、mode radios、`#apply-hint`、`#reset-config`、`#apply`、`#save-apply` |
| 接管哪些 AI 面板 | 范围摘要（"已接管 N 家 · 共 M 家"）、`显示本机没装的` 复选、执行器列表 | `#scope-summary`、`#show-all`、`#harness-list` |
| 默认命令启动（可折叠） | 说明「只决定裸敲 `metis` 时启动谁，不改变上面的应用范围」+ 默认执行器下拉 + `保存启动设置` | `#default-form`、`#default-harness` |

**执行器行（列表项）**：每行显示

```
[图标] 名称 · 版本        [已装/未装]      通道开关组         [详情 ▾]
```

- 通道开关：`接管命令(shim)` / `常驻(install)` / `会话内(slash)` / `项目(project)`，各自三态：
  **开**、**关**、**不可用（灰 + 悬停/展开说明 why）**。
- `详情` 展开后显示：落点文件路径（等宽字体）、层级（system / developer / user）、热切能力
  （`下一轮生效` / `需新会话`，以及为什么）、本次生效的人设与模式（含"来自分家例外"标记）、
  基线里的残留说明。
- 未安装的执行器默认折叠在"显示本机没装的"之后，且它的开关全部为不可用并说明原因（"PATH 里找不到 `codex`"）。

### 2.2 人设库（Library）

| 区块 | 内容 | 基线对应 |
|---|---|---|
| 页头 | 标题「人设库」+ 副标题「正文用于提示词，名称与说明只用于管理。」；`从外部拉取`、`新建人设` | `#pull-personas`、`#new-persona` |
| 列表 | 搜索框 + 人设卡片列表（名称、id、描述、当前使用标记、字数）；点击选中 | `#persona-search`、`#persona-list` |
| 编辑器 | id（只读或受限编辑）、名称、描述、model/harness 标签、正文多行编辑 + 实时字数、`保存`、`删除` | `#edit-id`、`#edit-name`、`#edit-desc`、`#edit-body`、`#char-count`、`#save-persona`、`#delete-persona` |
| 导入对话框 | 来源（本地目录 / GitHub `owner/repo`）、是否覆盖同名、进度与逐条结果、`开始导入`、`取消` | `#import-dialog`、`#import-source`、`#import-overwrite`、`#start-import` |
| 更新对话框 | 当前版本 / 最新版本、变更日志、可复制的升级命令、GitHub 链接、`直接升级`（仅便携安装可用） | `#version-badge`、`#update-*` |

规则：

- 只有**正文**进入提示词；名称、描述、标签只用于管理。界面上要写明这一点。
- `active` 是保留标识，不能作为人设名（保存时报错并指出）。
- 保存保留表单未涉及的元数据（例如用 CLI 加的自定义键）。
- `删除` 需要二次确认；`撤销接管` 不删人设，`删除数据` 才删，两者文案必须不同。

### 2.3 验证与诊断（Diagnostics）

| 区块 | 内容 | 基线对应 |
|---|---|---|
| 页头 | 标题「验证与诊断」+ 副标题「磁盘同步与真实请求验证分开记录。」；`重新同步已选范围` | `#sync-all` |
| 最近一次应用 | 报告元信息（时间、人设、模式、revision、成功/失败计数）；结果表格（执行器 / 通道 / 状态 / 生效时机 / 文件 / 错误）；`重试失败项` | `#report-meta`、`#apply-results`、`#retry-failed` |
| 真实请求验证 | 徽标「独立测试」；`开始验证`（选执行器）；结果：每家落在哪个角色、命中字数、抓到的请求摘要、失败原因 | `#capture-results` |
| 诊断信息 | 数据目录路径（可点击打开）、state 文件路径与体积、锁状态、日志目录；`打开数据目录` | `#diagnostic-state` |

**必须显眼的一句**（基线里反复强调的产品语义，界面上要有）：验证只证明"请求里有没有人设"，
不证明"模型听不听话"；也不测试用户自己的中转。

### 2.4 关于（About）

Metis 版本、构建信息、许可、文档链接、`检查更新`、`导入 agent-purge 数据`（见 `DATA-FORMAT.md` §5）、
`打开数据目录`、`卸载数据`（二次确认 + 先备份）。

## 3. 状态管理

```rust
pub struct AppState {
    pub screen: Screen,
    pub domain: DomainSnapshot,     // 来自 engine 的只读快照：state、personas、caps、detect
    pub draft: DraftState,          // 界面上还没保存的编辑
    pub jobs: JobsView,             // 进行中的任务与最近结果
    pub dialogs: DialogState,       // 导入 / 更新 / 确认 / 执行器详情展开
    pub notice: Option<Notice>,     // 顶部的临时提示
    pub ui: UiState,                // 面板宽度、列表滚动、折叠状态（serde 持久化）
}
```

- `DomainSnapshot` 只由 engine 产出（`metis-engine` 的 `snapshot()` 命令），UI 不自己拼。
- `DraftState` 是 UI 状态，**不进 `state.json`**；只有用户点"应用变更"才通过命令写回。
- `dirty` 由 `draft != domain` 计算；有脏数据时离开当前屏幕或关闭窗口要确认。
- 所有列表的排序/筛选是本地纯函数，放到 `metis-ui-egui` 的 `model.rs`，不依赖 egui 类型，**因此可以直接单测**。

## 4. 后台任务与反馈

| 触发 | 表现 |
|---|---|
| 探测（启动时、`刷新状态`） | 执行器列表显示骨架/加载中；完成后逐行就绪 |
| `应用变更` | 按钮忙碌态；顶栏显示"应用中…"；完成后弹出结果摘要，失败项在诊断页高亮，可直接"重试失败项" |
| `开始验证` | 进度条（按执行器推进）+ `取消`；取消后已完成的保留 |
| `检查更新` / 下载 | 进度 + `取消`；失败给出可复制的补救命令 |
| 导入人设 | 逐条结果流式追加；失败的条目保留在列表里 |
| 任何不可取消的长任务 | 明确标注"此步不可取消"（例如正在 rename） |

**错误呈现三级**：行内（字段级）→ 面板级（这一块失败）→ 通知条（整体操作失败）。任何错误都要带
`remediation`（补救建议），能复制。

## 5. 主题与视觉 token

沿用基线的配色（它是产品的一部分），转成主题 token；颜色只出现在 `theme.rs`，别处只引用 token 名。

| token | 浅色 | 用途 |
|---|---|---|
| `bg.page` | `#f6f7f9` | 页面背景 |
| `bg.surface` | `#ffffff` | 面板/卡片 |
| `text.primary` | `#101828` | 正文标题 |
| `text.secondary` | `#344054` | 次级文字 |
| `text.muted` | `#5d6b81` | 帮助文字 |
| `accent.default` | `#2459cf` | 主操作 |
| `accent.hover` | `#1d4ab2` | 主操作悬停 |
| `state.success` | `#067647` | 成功 |
| `state.warning` | `#93370d` | 警告 |
| `state.error` | `#b42318` | 错误 |
| `border.default` | 由 `bg.surface` 派生 | 分隔线、卡片描边 |

- 字体：优先系统 CJK 字体（`Microsoft YaHei UI` / `PingFang SC` / `Noto Sans CJK SC`），内置一份
  等宽字体用于路径与代码；不引入需要联网下载的字体。字体许可证随仓库（`assets/fonts/`）。
- 字号：正文 14，次级 13，标题 22，路径等宽 13。
- 间距：4 / 8 的倍数；圆角 6 / 8 / 12。
- **状态色永远附文字**，不能只靠颜色区分（色觉障碍 + 无障碍）。
- 深色主题：M1 只做浅色（与基线一致），但 token 结构预留；深色作为独立路线图条目。
- 图标：Lucide 风格的 SVG，本地资产，运行期光栅化（`egui_extras` 的 `svg` feature）。

## 6. 键盘与无障碍

- 全部可操作项键盘可达；可见焦点框；`Tab` 顺序与视觉顺序一致。
- 快捷键：`Ctrl+R` 刷新状态、`Ctrl+Enter` 应用变更、`Ctrl+K` 跳转到搜索、`Esc` 关闭对话框、
  `Alt+1..4` 切屏。
- 通过 egui 的 accesskit 集成暴露语义角色与名称；通知条用 live region。
- 支持"减少动效"（系统设置优先，其次应用内开关）：关掉过渡动画。
- 不用纯图标表达只有一种含义的操作（危险操作必须有文字）。

## 7. 布局验证

基线的 Web 版按 1440/768/390/320 四个宽度验证无横向溢出。桌面版对应改为：

| 用例 | 要求 |
|---|---|
| 最小窗口 `900×620` | 无横向滚动；执行器行折叠成两行；模式三选一变纵向 |
| 默认 `1280×860` | 双栏（列表 + 详情） |
| 最大 `2560×1440` | 内容最大宽度受限，不拉伸成一片空白 |
| 长文本 | 超长路径/错误信息换行或省略 + 悬停全文，绝不撑破布局 |
| 高 DPI（150%、200%） | 布局不重叠、图标不模糊 |

## 8. 国际化

- 界面语言：`zh-Hans`（默认）、`en`。文案集中在 `crates/ui-egui/src/i18n/`，采用 **TSV 表**
  （`键 \t 文案`，每语言一个文件），编译期嵌入，缺键时回退到 `zh-Hans` 并在 debug 构建里断言失败。
- 引擎产出的**用户可见字符串**（能力表的 `why`、错误 `message`、`remediation`）也走同一套键，
  不允许在 `metis-harness` / `metis-engine` 里硬编码中文再让 UI 显示。
  这是"结构化结果"原则的延伸：判定用字段，展示用键。
- CLI 输出沿用界面语言（`--lang` 或 `METIS_LANG` 覆盖），保证 CLI 与 GUI 文案一致。

## 9. 界面测试（egui_kittest）

- 每个屏幕至少一条渲染测试 + 一条关键交互测试（例如：改模式 → `应用变更` 按钮变为可用 → 点击后
  出现忙碌态）。
- 能力表驱动的用例：某家通道不可用时，断言开关**不可点**且**显示了 why**。
- 快照测试（`egui_kittest` 的 `snapshot` feature）覆盖：控制台默认态、执行器详情展开态、
  应用失败态（含重试按钮）、诊断页有报告态、人设编辑器脏态。
- 快照图像变动必须在 PR 里说明原因并更新基线图。
- 界面测试**不连真实 harness、不碰真实 `$HOME`**：全部经 `testkit` 的临时 home 与假执行器。
